# Validation arc — six smoke runs

| Run | What we changed | What ran | What we learned |
|---|---|---|---|
| **1** | First attempt at the new wiring. Planner emits subtopics, framework spawns N gatherers in parallel, downstream rule writes a counter on the planner's investigation entity to track completion. | Planner emitted 3 subtopics ✓. Three parallel gatherers ran ✓ (~30s span). Each emitted clean per-subtopic findings ✓. **Counter rule wedged** on a template-variable substitution. | The counter rule needed a parent reference (`agent.loop.parent`) that the framework hadn't yet stamped on the entity at the moment our rule fired. Framework's safety mechanism caught it cleanly (refused to write a triple with a garbled subject) — chain wedged but visibly. |
| **2** | Added a wait condition (`agent.loop.outcome=success`) to the counter rule hoping the parent reference would land first. | Same wedge as run 1. | The framework stamps the outcome marker and the parent reference in the same millisecond, but the rule engine processes them as separate updates. There's a race window between when our rule fires (outcome arrived) and when it tries to substitute the parent reference (still missing). |
| **3** | No new code — just confirmed the timing issue is structural, not flaky. Also surfaced a separate problem where some parallel gatherers terminated with prose instead of a structured terminal. | Same wedge. Plus 2 of 3 gatherers in run-3 returned prose text (~219 tokens) that went into the void — framework treated as success with empty result. | **Two upstream issues filed.** [semstreams#159](https://github.com/C360Studio/semstreams/issues/159) for the parent/outcome stamp race (proposed atomic batch OR stamp-parent-at-spawn). [semstreams#158](https://github.com/C360Studio/semstreams/issues/158) for the text-only completion handling (framework has `tool_choice=required` that prevents this; documented unblock applied to our spawn rule). |
| **4** | Sidestepped the race in #159 by stamping a separate spawn-time reference to the parent's full ID, then pointing the counter rule at that reference instead. Spawn-time stamps are stable long before completion. | Counter rule fired without the race error ✓. **But all 4 counter writes landed on a phantom subject** (`<plan-uuid>-entity`). | Template-variable substitution does ReplaceAll per variable in Go-map iteration order. We named the new lineage triple `lineage.researcher-plan-entity`, but `lineage.researcher-plan` shared a prefix and replaced first, leaving `-entity` orphaned. **Filed [semstreams#160](https://github.com/C360Studio/semstreams/issues/160)** proposing longest-name-first iteration. |
| **5** | Renamed our lineage triple to `lineage.plan-loop-entity-id` (no prefix collision with `lineage.researcher-plan`). | Counter accumulated correctly on the real parent ✓. Join rule fired when N=4 ✓. Aggregator ran ✓. **First reviewer pass emitted `insufficient`** (substance review, not pipeline failure) — recovery path correctly re-planned and re-fanned-out. **But the recovery cycle's aggregator hit the same text-only-completion issue from #158**, on a different role this time. | Chain reached aggregator + reviewer + recovery correctly — that's structural-validation green. Recovery cycle wedged because we'd only applied `tool_choice=required` to the parallel-gatherer spawn rule. The same guard needs to apply to every flash-model spawn (aggregator, reviewer, recovery planner). |
| **6** | Applied `tool_choice=required` to every flash-model spawn rule in the pack (planner spawn, aggregator spawn, reviewer spawn, recovery-replan spawn). | **Full chain end-to-end. ~2 min wallclock. ~$0.30 spend. Reviewer approved without recovery.** Coordinator wake-up emitted respond_direct. 8 loops total. | This is the canonical happy path. Substance review passed on the first reviewer pass. The recovery path was validated in run 5; this run validated the no-recovery path. |

## Summary

- **3 upstream issues filed**, 2 already addressed at the framework layer, 1 ([#159](https://github.com/C360Studio/semstreams/issues/159)) in design discussion
- **1 workaround temporarily in our code** (2-line spawn-time lineage triple) — retires when #159 lands
- **1 documented-pattern adoption** (`tool_choice=required` on every flash-model spawn) — matches the framework's beta.80 closure-pass guidance
- **0 application-side state machinery** built to compensate for framework gaps — discipline held

## What each smoke cost

Each smoke run booted a backend stack, ran the chain against real Gemini, captured trajectories + message logs + triple snapshots to `/tmp/fan-out-validation-N/`, and tore down. Rough per-run cost: ~$0.15-$0.50 depending on how far the chain progressed before wedging. Total cycle spend: well under $5.
